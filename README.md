# Hermes для Excel

> **Агенту, который это ставит:** пошаговая процедура установки и проверки — в [AGENTS.md](AGENTS.md).
> Он написан так, чтобы его можно было выполнить командой за командой и проверить результат на каждом шаге.
> Быстрая проверка «всё ли живо» — одной командой: `scripts\doctor.cmd`.
>
> ВАЖНО про примеры `curl` ниже: POST-эндпоинты требуют заголовок `X-Hermes-Bridge: 1`, а тело —
> строго UTF-8. `curl -d '{"prompt":"кириллица"}'` из git-bash отправляет cp1251, и мост отвечает
> `400 тело запроса не разобралось как UTF-8 JSON` (это защита от прогона с пустым промптом).
> Для кириллицы пишите тело в файл и передавайте `--data-binary @file.json`.
> В AGENTS.md шаг 6 пока без этих двух уточнений — раздел обновляется отдельно.

Надстройка Excel, внутри которой работает **Hermes Agent** — с любыми моделями (свои провайдеры,
локальные эндпоинты, BYOK) и с полноценными инструментами агента. Чат, начатый в Excel, живёт в
общем сторе сессий Hermes: его можно продолжить в desktop-приложении, в CLI (`hermes --resume <id>`)
или в веб-дашборде. Сессия одна — поверхность любая.

## Как это устроено

```
Excel (Office.js task pane)  ──HTTPS+SSE──►  bridge.py (localhost:3443)
      │                                            │  spawn
      │   ◄── дельты ответа, лог инструментов ──────┤
      │                                            ▼
      └── запись результата в лист            hermes -p excel chat --format stream-json
          (текст / CSV-блок / формулы)         --resume <session> -m <model> -t file
                                                    │
                                                    ▼
                                profiles/excel/state.db  (сессии бота Excel)
                                                    │
                              ┌─────────────────────┴─────────────────────┐
                        desktop-приложение Hermes                  hermes --resume
                        (вкладка Bots → Excel)                     (CLI, web-дашборд)
```

* **Модель выбирается на каждое сообщение** — выпадающий список строится из кэша моделей Hermes
  (`provider_models_cache.json`), плюс вариант `auto` (модель по умолчанию). Модели и провайдеры,
  настроенные в Hermes, доступны в Excel без отдельной подписки.
* **Мост — единственная точка входа**: статика надстройки и API живут на одном origin
  (`https://localhost:3443`), поэтому нет CORS-проблем, а наружу ничего не выставляется
  (bind только на 127.0.0.1).
* **Контекст листа** уходит модели как CSV выделенного диапазона (до 400 строк × 60 колонок),
  с указанием файла, листа и адреса диапазона.
* **Возврат в книгу**: панель находит в ответе блоки ```csv / ```formulas, показывает превью того,
  что уедет в лист, и раскладывает результат от ячейки, которая была выделена **в момент отправки**.

## Запуск

### Новая машина — одна команда

```powershell
git clone https://github.com/MaratAhmetzyanov83/hermes-excel.git "$env:USERPROFILE\hermes-excel"
cd "$env:USERPROFILE\hermes-excel"
.\install.cmd            # сертификаты → бот → сайлоад → сторож → мост → doctor
.\doctor.cmd             # таблица проверок с командами-исправлениями
```

Установка идемпотентна: повторный запуск ничего не ломает и ничего не переделывает.
`install.cmd -DryRun` — показать план; `-Profile <имя>` — другое имя бота; `-NoBridge` — без сторожа.
Если сертификата нет и Node не установлен, установщик выдаст его через `openssl` из git-bash и добавит
в доверенные корни — **Node не обязателен**. Снять всё: `scripts\uninstall.ps1`.

**В git-bash / MSYS запускайте `./install.sh` и `./doctor.sh`** — это те же скрипты, но без ловушки cmd:
`cmd //c install.cmd` в MSYS калечится (`//c` съедается), и вместо установки открывается интерактивная
консоль cmd, в которой агент висит. В cmd/PowerShell работают `install.cmd` / `doctor.cmd`.

Агенту, которого вы отправите настраивать другую машину, достаточно сказать:
«склонируй https://github.com/MaratAhmetzyanov83/hermes-excel и поставь надстройку: запусти установку
(в PowerShell/cmd — `install.cmd`, в git-bash — `./install.sh`), затем проверку (`doctor.cmd` или
`./doctor.sh`) — все строки должны стать PASS. Инструкция, порядок проверки и грабли — в AGENTS.md».

### Те же шаги вручную

```bash
# 1. Сертификаты для https://localhost (один раз)
npx --yes office-addin-dev-certs install --days 365

# 2. Регистрация надстройки в Excel (один раз)
powershell -ExecutionPolicy Bypass -File scripts/sideload.ps1

# 3. Сторож: держит мост живым (задача раз в минуту + автозапуск при входе в Windows)
powershell -ExecutionPolicy Bypass -File scripts/install-watchdog.ps1

# 4. Книга, которая САМА открывает панель (кликать ничего не нужно)
python scripts/auto-open-workbook.py create

# далее в любой момент: одна команда — мост + Excel с панелью
start-bridge.cmd excel
```

### Автозапуск и сторож («чтобы работало, когда просто открыл Excel»)

Раньше автозапуск был только ярлыком в «Автозагрузке», а он срабатывает **один раз при входе в
Windows**: упал мост или не поднялся — панель открывается против мёртвого сервера, и лечится это
только руками. Теперь мост держит сторож (`scripts/bridge-watchdog.ps1`):

* раз в минуту проверяет `https://localhost:3443/health` и поднимает мост, если тот не отвечает
  (только когда запущен Excel, если не передан `-Force`);
* при входе в Windows ярлык автозагрузки вызывает его с `-Force` — мост есть сразу, не через минуту;
* если порт занят, а `/health` молчит (зависший старый мост) — снимает зависший процесс и поднимает свой;
* замок сторожа «стареет» через 3 минуты: зависший запуск не блокирует всех остальных;
* ищет интерпретатор перебором с проверкой запуском: **заглушка Microsoft Store**
  (`…\WindowsApps\python.exe`) — не python, она печатает «Python» и выходит;
* пишет всё в `workspace/watchdog.log`, а сам мост — в `workspace/bridge.log`.

Снять автозапуск: `scripts\install-watchdog.ps1 -Remove`. Состояние: `start-bridge.cmd status`.

### Как надстройка попадает в Excel (важное, проверено на этой машине)

* **Работает:** `HKCU\Software\Microsoft\Office\16.0\WEF\Developer` — значение с именем `<Id надстройки>`
  и данными = полный путь к `manifest.xml`. Это тот же механизм, которым у вас поставлены
  Pi for Excel и DeepSeek-Office-Addin.
* **Не работает на этой машине:** `TrustedCatalogs` (доверенный каталог) — Office кэширует список
  каталогов в `Wef\AppCommands\11.0\TrustedCatalog\` и мои записи туда не попадали ни с локальным
  путём, ни с UNC `\\localhost\C$\...`, ни после перезапуска Excel. Ключ оставлен на будущее,
  но полагаться на него не нужно.
* **Надстройка не появляется на ленте, пока её не активируют один раз в процессе Excel.** Поэтому
  панель поднимают из документа: книга `workspace/hermes-auto.xlsx` несёт часть `xl/webextensions`
  с `<we:reference id="<Id>" version="1.0.0.0" store="developer" storeType="Registry"/>`, и Excel
  открывает панель сам при открытии книги. После этой первой активации кнопка «Hermes Agent»
  появляется на вкладке «Главная» до конца сеанса Excel.

Проверить, что панель действительно живёт внутри Excel, можно без скриншотов: в `workspace/bridge.log`
появятся запросы вида `GET /taskpane.html?_host_Info=Excel$Win32$16.01$ru-RU$$$$0`, затем `/models`
и `/sessions`, а Office закэширует манифест в `Wef/{guid}/…/Manifests/<Id>_1.0.0.0`.


## Бот для Excel (отдельный профиль + свои сессии)

Чат в панели ведёт **не основной профиль, а отдельный бот** — профиль Hermes `excel`: свой конфиг,
свой `SOUL.md`, свои скиллы, своя память и **свой стор сессий**
(`~/AppData/Local/hermes/profiles/excel/state.db`). Сессии Excel не смешиваются с вашими рабочими
сессиями в default, и у бота своя модель по умолчанию (`deepseek-flash` — панель отвечает быстро).

```bash
# создать бота (один раз; --clone переносит конфиг, ключи и скиллы из default)
hermes profile create excel --clone --description "Excel-бот: живёт в надстройке Excel"
hermes -p excel config set model.provider deepseek
hermes -p excel config set model.default deepseek-flash

# пообщаться с ним как обычно
hermes -p excel chat                     # или: excel chat   (обёртка-алиас)
hermes -p excel sessions list            # ВСЕ сессии бота (в т.ч. начатые в Excel)

# в desktop-приложении бот виден на вкладке Bots; его канонический чат — «Excel»
```

Мост берёт профиль из переменной `HERMES_BRIDGE_PROFILE` (по умолчанию `excel`; пустое значение или
`default` — работа в основном профиле). Панель показывает, с кем говорит: «мост на связи · бот excel».

Что даёт такая схема, кроме изоляции:

* **память бота** — он помнит ваши привычки в таблицах, не засоряя основной профиль;
* **свои скиллы** — у бота лежит `excel-pane-contract` (формат ответа: ```csv / ```formulas);
* **свой `SOUL.md`** — характер и правила ответа под узкую панель (короткие ответы, блоки для вставки);
* **кнопка «открыть в Hermes»** в панели открывает `hermes -p excel chat --resume <id>`;
* один и тот же разговор можно продолжать в Excel, в desktop (Bots → Excel) и в CLI.

Ходы панели запускаются узким набором инструментов (`-t file`) с предзагруженным контрактом
(`-s excel-pane-contract`) и бюджетом прогона (`--run-budget`): промпт вдвое короче, и агент не тратит
круги на попытки вызвать недоступное. Расширить: `HERMES_BRIDGE_TOOLSETS=file,web`.


## Использование

1. Выделите диапазон в листе — CSV подтянется в панель автоматически (можно править руками;
   правки больше не затираются при движении выделения — есть кнопка «обновить из листа»).
2. Выберите модель/провайдера (или оставьте `auto`), напишите задачу, «Спросить Hermes».
3. Пока идёт ход, в пузыре ответа **с первой секунды** видно время и число вызовов инструментов,
   а ниже — сами вызовы: панель не выглядит зависшей на длинных задачах.
4. Под ответом: **превью** блоков («это уедет в лист»), кнопки записи, «скопировать ответ»,
   «скопировать CSV». Если целевые ячейки **не пустые**, автозапись не срабатывает молча — панель
   спросит: «перезаписать N×M», «записать в текущее выделение», «не писать».
5. После записи тост показывает, **куда** легли данные, и предлагает «Отменить» (10 секунд) —
   откат возвращает прежнее содержимое, включая формулы.
6. Кнопка «открыть в Hermes» открывает **эту же** сессию в Hermes CLI. Ниже — список последних
   сессий: можно продолжить в Excel любой чат, начатый в desktop/CLI. При перезапуске Excel панель
   восстанавливает ленту последних реплик сессии книги (`GET /session?id=…`).

## Безопасность

* Мост слушает только `127.0.0.1`. POST-эндпоинты требуют кастомный заголовок `X-Hermes-Bridge: 1`
  (его нельзя поставить «простым» межсайтовым запросом без preflight) **и** свой `Origin`.
  `Origin: null` (песочница `<iframe sandbox>`, `data:`, `file:`) запрещён — иначе любая открытая
  веб-страница могла бы запускать агента на этой машине. Запросы без `Origin` (curl/CLI) проходят.
* Статика отдаётся только из `addin/`: путь нормализуется и проверяется (`relative_to`), обход
  каталога (`/assets/../../…`) невозможен.
* `POST /open` запускает Hermes **без shell**, а `session_id` проверяется строгой маской —
  подстановка команд (`"zz & calc.exe"`) не проходит.
* `POST /stop` останавливает только указанный прогон (`run_id`, иначе свою сессию); пустой запрос
  не убивает ничего. Таймаут прогона сторожит отдельный поток и снимает процесс вместе с потомками.
* Тело запроса принимается только как UTF-8 JSON; иначе — `400` и запись в лог (раньше мост молча
  стартовал прогон с пустым промптом).
* Агент внутри Excel имеет **полный доступ к инструментам** (терминал, файлы, браузер), как обычная
  сессия Hermes. Если это не нужно — ограничьте набор инструментов через параметр `toolsets` в
  `/chat` или запускайте мост только на время работы.
* Всё, что делает агент по файлам, оседает в `workspace/`; файлы запросов пишутся в `%TEMP%\hermes-bridge`.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| «Ничего не запускается», панель пишет «мост не запущен» | запустите `scripts\doctor.cmd` — он покажет, что именно не так, с командой-исправлением. Мост поднять: `start-bridge.cmd` или `start-bridge.cmd excel` |
| Мост снова лёг после перезагрузки/падения | сторож не поставлен: `powershell -File scripts\install-watchdog.ps1`; проверка — `start-bridge.cmd status` (задача должна быть `Ready`, результат `0x0`) |
| В `workspace\bridge.err.log` одинокая строка `Python` | в PATH первым оказалась заглушка Microsoft Store; сторож перебирает интерпретаторы сам (venv Hermes → проект → PATH кроме `WindowsApps` → `py -3`) |
| `curl: (35) CRYPT_E_NO_REVOCATION_CHECK` | curl на Windows идёт через Schannel и не находит CRL у локального CA; это только для curl — Excel/WebView2 доверяют сертификату. Для curl добавьте `--ssl-no-revoke` |
| `400 тело запроса не разобралось как UTF-8 JSON` | тело отправлено не в UTF-8 (типично: кириллица в `curl -d` из git-bash). Пишите тело в файл и используйте `--data-binary @file.json` |
| Excel не видит надстройку | сайлоад идёт через `HKCU\...\WEF\Developer` (Id → путь к manifest.xml), а не через «Общую папку»; после правки реестра Excel надо перезапустить |
| Панель не открылась сама | откройте `workspace/hermes-auto.xlsx` (в книге лежит часть `xl/webextensions` с авто-открытием) — либо нажмите «Hermes Agent» на вкладке «Главная» |
| Ответ приходит медленно | каждая реплика — отдельный процесс `hermes chat` (старт ~2–4 с, кэш промпта ускоряет повторные ходы). Для диалога в книге удобнее быстрые модели (`deepseek-flash`, `gpt-5-mini`, `glm-5.3-flash`). Замер: `python scripts/bench-turn.py` |
| Служебная ошибка провайдера вместо ответа | теперь приходит как красный пузырь с подсказкой-командой (`hermes -p excel auth add …`), а не как текст модели |
| Оборвалась длинная задача | `--max-turns` по умолчанию 40, бюджет прогона `HERMES_BRIDGE_RUN_BUDGET` (240 с), жёсткий таймаут `HERMES_BRIDGE_TIMEOUT` |

## Ограничения, о которых стоит знать

* Одна реплика = один процесс `hermes chat`: сессия продолжается по `--resume`, промпт-кэш
  переиспользуется, но «живого» стрима в desktop одновременно с Excel нет — статус подхватывается,
  когда ход завершён (это ограничение CLI-моста, а не Hermes: тот же backend-сервер `hermes serve`
  поверх WebSocket-протокола даёт именно живую синхронизацию, и это следующий шаг).
* Панель не умеет показывать картинки/графики — только текст, CSV и формулы.
* На Windows закрытие окна Excel не убивает мост: `start-bridge.cmd stop` (сторож поднимет его снова —
  чтобы остановить надолго, сначала `scripts\install-watchdog.ps1 -Remove`).
