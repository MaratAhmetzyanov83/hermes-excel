# Hermes для Excel

> **Агенту, который это ставит:** пошаговая процедура установки и проверки — в [AGENTS.md](AGENTS.md).
> Он написан так, чтобы его можно было выполнить командой за командой и проверить результат на каждом шаге.

Надстройка Excel, внутри которой работает **Hermes Agent** — с любыми моделями (свои провайдеры,
локальные эндпоинты, BYOK) и с полноценными инструментами агента. Чат, начатый в Excel, живёт в
общем сторе сессий Hermes: его можно продолжить в desktop-приложении, в CLI (`hermes --resume <id>`)
или в веб-дашборде. Сессия одна — поверхность любая.

## Как это устроено

```
Excel (Office.js task pane)  ──HTTPS+SSE──►  bridge.py (localhost:3443)
      │                                            │  spawn
      │   ◄── дельты ответа, лог инструментов ──────┤
      │                                            ▼
      └── запись результата в лист            hermes chat --format stream-json
          (текст / CSV-блок / формулы)         --resume <session>  -m <model>
                                                    │
                                                    ▼
                                       ~/.hermes/state.db  (общий стор сессий)
                                                    │
                              ┌─────────────────────┴─────────────────────┐
                        desktop-приложение Hermes                  hermes --resume
                        (тот же список сессий)                     (CLI, web-дашборд)
```

* **Модель выбирается на каждое сообщение** — выпадающий список строится из кэша моделей Hermes
  (`provider_models_cache.json`), плюс вариант `auto` (модель по умолчанию). Модели и провайдеры,
  настроенные в Hermes, доступны в Excel без отдельной подписки.
* **Мост — единственная точка входа**: статика надстройки и API живут на одном origin
  (`https://localhost:3443`), поэтому нет CORS-проблем, а наружу ничего не выставляется
  (bind только на 127.0.0.1).
* **Контекст листа** уходит модели как CSV выделенного диапазона (до 400 строк × 60 колонок),
  с указанием файла, листа и адреса диапазона.
* **Возврат в книгу**: кнопки «текст в ячейку», «CSV-блок в лист», «формулы» — панель сама
  находит в ответе блок ```csv или ```formulas и раскладывает его от активной ячейки.

## Файлы

| Путь | Что это |
|---|---|
| `bridge/bridge.py` | локальный HTTPS-мост (stdlib Python, без зависимостей) |
| `addin/manifest.xml` | манифест надстройки (проверен `office-addin-manifest validate`) |
| `addin/taskpane.html/.js/.css` | панель: модели, контекст, стрим ответа, запись в лист |
| `catalog/manifest.xml` | копия манифеста для каталога доверенных надстроек Excel |
| `scripts/sideload.ps1` | регистрация каталога в реестре (HKCU, без прав администратора) |
| `scripts/make-icons.py` | иконки 16/32/64/80 |
| `scripts/auto-open-workbook.py` | книга с авто-открытием панели (`create` / `tag`) |
| `scripts/autostart-install.ps1` | (опционально) автозапуск моста при входе в Windows |
| `start-bridge.cmd` | `start-bridge.cmd` — старт, `start-bridge.cmd stop` — остановка |
| `workspace/` | рабочая папка агента (сюда он пишет файлы, отсюда читает) |

## Запуск

```bash
# 1. Сертификаты для https://localhost (один раз)
npx --yes office-addin-dev-certs install --days 365

# 2. Регистрация надстройки в Excel (один раз)
powershell -ExecutionPolicy Bypass -File scripts/sideload.ps1

# 3. Мост
start-bridge.cmd            # или: python bridge/bridge.py

# 4. Книга, которая САМА открывает панель (кликать ничего не нужно)
python scripts/auto-open-workbook.py create workspace/hermes-auto.xlsx
```

### Как надстройка попадает в Excel (важное, проверено на этой машине)

* **Работает:** `HKCU\Software\Microsoft\Office\16.0\WEF\Developer` — значение с именем `<Id надстройки>`
  и данными = полный путь к `manifest.xml`. Это тот же механизм, которым у вас поставлены
  Pi for Excel и DeepSeek-Office-Addin.
* **Не работает на этой машине:** `TrustedCatalogs` (доверенный каталог) — Office кэширует список
  каталогов в `Wef\AppCommands\11.0\TrustedCatalog\` и мои записи туда не попадали ни с локальным
  путём, ни с UNC `\\localhost\C$\...`, ни после перезапуска Excel. Ключ оставлен на будущее,
  но полагаться на него не нужно.
* **Надстройка не появляется на ленте, пока её не активируют один раз в процессе Excel.** Поэтому
  панель поднимают из документа: книга `workspace/hermes-auto.xlsx` несёт часть `xl/webextensions`
  с `<we:reference id="<Id>" version="1.0.0.0" store="developer" storeType="Registry"/>`, и Excel
  открывает панель сам при открытии книги. После этой первой активации кнопка «Hermes Agent»
  появляется на вкладке «Главная» до конца сеанса Excel.

Проверить, что панель действительно живёт внутри Excel, можно без скриншотов: в `workspace/bridge.log`
появятся запросы вида `GET /taskpane.html?_host_Info=Excel$Win32$16.01$ru-RU$$$$0`, затем `/models`
и `/sessions`, а Office закэширует манифест в `Wef/{guid}/…/Manifests/<Id>_1.0.0.0`.


## Бот для Excel (отдельный профиль + свои сессии)

Чат в панели ведёт **не основной профиль, а отдельный бот** — профиль Hermes `excel`: свой конфиг,
свой `SOUL.md`, свои скиллы, своя память и **свой стор сессий**
(`~/AppData/Local/hermes/profiles/excel/state.db`). Сессии Excel не смешиваются с вашими рабочими
сессиями в default, и у бота своя модель по умолчанию (`deepseek-flash` — панель отвечает быстро).

```bash
# создать бота (один раз; --clone переносит конфиг, ключи и скиллы из default)
hermes profile create excel --clone --description "Excel-бот: живёт в надстройке Excel"
hermes -p excel config set model.default deepseek-flash

# пообщаться с ним как обычно
hermes -p excel chat                     # или: excel chat   (обёртка-алиас)
hermes -p excel sessions list            # ВСЕ сессии бота (в т.ч. начатые в Excel)

# в desktop-приложении бот виден на вкладке Bots; его канонический чат — «Excel»
```

Мост берёт профиль из переменной `HERMES_BRIDGE_PROFILE` (по умолчанию `excel`; пустое значение или
`default` — работа в основном профиле). Панель показывает, с кем говорит: «мост на связи · бот excel».

Что даёт такая схема, кроме изоляции:

* **память бота** — он помнит ваши привычки в таблицах, не засоряя основной профиль;
* **свои скиллы** — у бота уже лежит `excel-pane-contract` (формат ответа: ```csv / ```formulas);
* **свой `SOUL.md`** — характер и правила ответа под узкую панель (короткие ответы, блоки для вставки);
* **кнопка «открыть в Hermes»** в панели открывает `hermes -p excel chat --resume <id>`;
* один и тот же разговор можно продолжать в Excel, в desktop (Bots → Excel) и в CLI.


## Использование

1. Выделите диапазон в листе — CSV подтянется в панель автоматически (можно править руками).
2. Выберите модель/провайдера (или оставьте `auto`), напишите задачу, «Спросить Hermes».
3. Ответ стримится по мере генерации; внизу видно, какие инструменты вызывал агент.
4. Кнопками под ответом положите результат в лист; кнопка «открыть в Hermes» откроет **эту же**
   сессию в Hermes CLI. Ниже — выпадающий список последних сессий Hermes: можно продолжить в Excel
   любой чат, начатый в desktop/CLI.

## Безопасность

* Мост слушает только `127.0.0.1`, проверяет заголовок `Origin` — посторонняя веб-страница
  не сможет дёрнуть `/chat` (запросы без `Origin`, т.е. curl/CLI, разрешены для отладки).
* Агент внутри Excel имеет **полный доступ к инструментам** (терминал, файлы, браузер), как обычная
  сессия Hermes. Если это не нужно — ограничьте набор инструментов через параметр `toolsets` в
  `/chat` или запускайте мост только на время работы.
* Всё, что делает агент по файлам, оседает в `workspace/`.

## Тесты без Excel

Панель проверяется оффлайн — на строгом моке Office.js, который ведёт себя как настоящий API
(свойства `Range` падают, если их не загрузили через `load()`):

```bash
python scripts/make-pane-test.py       # генерирует addin/test-office.html из настоящего taskpane.html
# затем открыть https://localhost:3443/test-office.html в браузере (или headless Chrome + --dump-dom)
```

Стенд реально ловит поломки: если вернуть в `taskpane.js` чтение незагруженного свойства, тест краснеет
с тем же сообщением, что видит пользователь в Excel («Свойство "address" недоступно…»).

## Диагностика

| Симптом | Причина / решение |
|---|---|
| Панель пишет «мост недоступен» | не запущен `bridge.py` (`start-bridge.cmd`), либо порт занят вторым экземпляром — мост специально падает с ошибкой «Порт занят» |
| `curl: (35) CRYPT_E_NO_REVOCATION_CHECK` | curl на Windows идёт через Schannel и не находит CRL у локального CA; это только для curl — Excel/WebView2 доверяют сертификату. Для curl добавьте `--ssl-no-revoke` |
| Excel не видит надстройку | сайлоад идёт через `HKCU\...\WEF\Developer` (Id → путь к manifest.xml), а не через «Общую папку»; после правки реестра Excel надо перезапустить |
| Панель не открылась сама | откройте `workspace/hermes-auto.xlsx` (в книге лежит часть `xl/webextensions` с авто-открытием) — либо, если надстройка уже активировалась в этом процессе Excel, нажмите кнопку «Hermes Agent» на вкладке «Главная» |
| Excel сам не открыл панель после обновления файлов | авто-открытие срабатывает один раз на процесс Excel: перезапустите Excel с этой книгой |
| Ответ приходит медленно | каждая реплика — отдельный процесс `hermes chat` (старт ~2–4 с, кэш промпта ускоряет повторные ходы). Для диалога в книге удобнее быстрые модели (`deepseek-flash`, `gpt-5-mini`, `glm-5.3-flash`) |
| Оборвалась длинная задача | `--max-turns` по умолчанию 40, таймаут прогона 30 минут (настраивается `HERMES_BRIDGE_TIMEOUT`) |

## Ограничения, о которых стоит знать

* Одна реплика = один процесс `hermes chat`: сессия продолжается по `--resume`, промпт-кэш
  переиспользуется, но «живого» стрима в desktop одновременно с Excel нет — статус подхватывается,
  когда ход завершён (это ограничение CLI-моста, а не Hermes: тот же backend-сервер `hermes serve`
  поверх WebSocket-протокола даёт именно живую синхронизацию, и это следующий шаг).
* Панель не умеет показывать картинки/графики — только текст, CSV и формулы.
* На Windows закрытие окна Excel не убивает мост: `start-bridge.cmd stop`.
